# Stage 2 — TODO المؤجّل

بخلاف Stage 1، لا يوجد هنا أي بند بسبب انعدام الإنترنت — Stage 2 بالكامل
لا يعتمد على أي حزمة خارجية أو تثبيت (Vanilla JS + Web Components + CSS
فقط)، فمفيش أي `npm install` أو اتصال شبكة مطلوب لتشغيل أي حاجة فيه.

البنود المؤجَّلة هنا كلها بسبب **قرارات منتج/معمارية لم تُتّخذ بعد**، مش
عوائق تقنية في بيئة التنفيذ:

---

## 1. قرار إطار عمل الموبايل النهائي (React Native / Flutter / Web-PWA)

- **الحالة الحالية:** `Mobile/` في Stage 1 لسه placeholder فارغ — القرار
  لم يُتّخذ بعد (موضّح في `DesignSystem/README.md`).
- **اللي اتعمل عشان الأثر يبقى صفر أيًا كان القرار:** كل Design Tokens
  محفوظة كـ JSON محايد (`tokens/*.json`) منفصل تمامًا عن أي كود استهلاك.
  الـ Components اتبنت كـ Web Components قياسية — لو القرار يبقى PWA/Web
  فعلي للموبايل، الكود ده يتستخدم زي ما هو.
- **المطلوب لاحقًا حسب القرار:**
  - لو React Native: إعادة كتابة طبقة الـ Components فقط بـ `StyleSheet`
    (أو `NativeWind`/`styled-components`) تقرأ من نفس `tokens/*.json` —
    الـ tokens نفسها متتغيرش.
  - لو Flutter: توليد `ThemeData` + Widgets من نفس `tokens/*.json`.
  - لو Web/PWA: لا شيء يتغيّر — الكود الحالي يُستخدم مباشرة.

## 2. توليد `tokens.css` تلقائيًا من `tokens/*.json`

- **الحالة الحالية:** `tokens.css` مكتوب يدويًا ومتطابق مع الـ JSON وقت
  كتابة هذا الملف (تم التحقق بالمقارنة المباشرة، انظر تقرير الـ Audit).
- **ليه مؤجَّل:** سكربت توليد (Node) يحتاج تشغيل حقيقي زي أي أداة بناء —
  مش blocker لعمل النظام دلوقتي لأن الملفين بيتحدّثوا مع بعض يدويًا في نفس
  التعديل، لكنه تحسين مفيد لمنع أي انحراف مستقبلي بين المصدرين.
- **المطلوب لاحقًا:** سكربت بسيط (`node scripts/build-tokens.js`) يقرأ
  الـ JSON ويكتب `tokens.css` تلقائيًا، يتشغّل يدويًا أو كخطوة CI.

## 3. [External Setup — Deferred] ربط الخطوط/الصور الحقيقية لو احتاج المشروع براند مخصص

- **الحالة الحالية:** لا توجد خطوط أو صور خارجية في Stage 2 عن قصد — كل
  الخطوط من نظام التشغيل (`tokens/typography.json` → `notes`)، وكل الأيقونات
  SVG داخلية (`icon-registry.js`). هذا يخلي النظام يعمل offline بالكامل
  بدون أي طلب شبكة.
- **المطلوب لاحقًا (فقط لو قرار البراند يحتاج خط مخصص):** رفع ملفات الخط في
  `DesignSystem/assets/fonts/` وتسجيلها في `tokens.css` — بدون أي تغيير في
  بنية الـ Components.

## 4. Navigation / Routing الحقيقي بين الشاشات

- **الحالة الحالية:** الانتقال Splash → Login في `screens/splash/index.html`
  مُنفَّذ بـ `window.location.href` كمحاكاة فقط (مطلوب صراحة في التعليمات
  ألا تكون الشاشتان Mockup منفصل، فتم ربطهما فعليًا بانتقال حقيقي يعمل في
  المتصفح الآن) — لكن نظام Routing حقيقي (Stack Navigation في تطبيق فعلي)
  هو قرار معماري يخص بناء التطبيق نفسه في Stage 3، مش جزء من Design System.
- **المطلوب لاحقًا:** يُبنى مع باقي شاشات التطبيق في Stage 3، فوق نفس
  الـ Components الموجودة هنا بدون تعديلها.

## 5. تسجيل الدخول الفعلي / الاتصال بـ Backend

- **الحالة الحالية:** زر "تسجيل الدخول" في `screens/login/index.html`
  يعمل Validation حقيقي على الحقول (بريد/كلمة مرور) ويُظهر حالة `[loading]`
  الحقيقية، لكن لا يتصل بأي API — ده محاكاة عرض فقط، ومقصود تمامًا حسب
  بند "لا تربط أي Cloud أو Server خارجي في هذه المرحلة".
- **المطلوب لاحقًا:** ربط فعلي بـ `Backend/` (من Stage 1) عند بناء منطق
  المصادقة في مرحلة لاحقة — لا حاجة لأي تعديل في Design System نفسه.
