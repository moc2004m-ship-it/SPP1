## الفئة أ) محتاج اتصال إنترنت فقط (مش حساب/خدمة خارجية)

### `Backend/package-lock.json` (تحديث)
- **الحالة:** تمت إضافة `pg` كـ dependency جديد في `package.json`، لكن
  `package-lock.json` مش موجود من الأساس (نفس وضع Stage 1) ولن يُخترع.
- **السبب:** جرّبت فعليًا `npm install` في بيئة التنفيذ الحالية ورجعت
  `403 Forbidden` من `registry.npmjs.org` — نفس القيد المسجل في
  `STAGE1_TODO.md`، بدون أي تغيير.
- **الأثر:** `npm install` (ومن ثم `npm test`, `npm start`, إلخ) لازم
  يتشغّل مرة واحدة على بيئة متصلة بالإنترنت (جهازك أو GitHub Actions) قبل
  أي تشغيل فعلي للـ backend بالكامل (Stage 1 كمان كانت متأثرة بنفس القيد).
- **ملاحظة مهمة:** اختبارات Stage 3 اللي **لا تحتاج** `express`/`pg`
  (id-generator, account model, account repository, reference model +
  repository) تم تشغيلها فعليًا بنجاح داخل بيئة التنفيذ الحالية (19/19
  ناجحة) رغم القيد ده — لأنها كود Node أصلي بدون أي مكتبة خارجية.
  اختبار الـ HTTP routes (`accounts.routes.test.js`) وحده يحتاج `express`
  المثبتة بالفعل من Stage 1، فهو ينتظر نفس `npm install`.

## الفئة ب) [External Setup — Deferred] — محتاج حساب/خدمة خارجية فعلية

### 1. الاتصال بقاعدة بيانات Postgres حقيقية
- **الحالة الحالية:** الكود **جاهز وشغّال فعليًا** ضد نسخة in-memory —
  نفس الواجهة (`create/findById/list`) موجودة في `PostgresAccountRepository`
  و`PostgresReferenceRepository` (`Backend/src/database/repositories/`).
- **المطلوب لاحقًا:**
  1. حساب قاعدة بيانات Postgres حقيقي (مُدار أو self-hosted).
  2. تعيين `DATABASE_URL` الحقيقي في بيئة التشغيل.
  3. تعيين `STAGE3_ENABLE_POSTGRES=true`.
  4. تشغيل `npm run migrate` لتطبيق ملفات `schema/*.sql` فعليًا.
- **لن يحدث تلقائيًا:** `src/database/index.js` بيرجع نسخة `memory`
  افتراضيًا دايمًا، حتى لو `DATABASE_URL` موجودة، لحد ما الـ flag يتفعّل
  صراحة — عشان محدش يفتكر إن فيه DB إنتاج حقيقية شغالة وهي مش موجودة.

### 2. تشغيل `migrate.js` فعليًا
- **الحالة الحالية:** الـ script جاهز (`Backend/src/database/migrations/migrate.js`)
  وبيرفض يعمل حاجة لحد ما يلاقي `STAGE3_ENABLE_POSTGRES=true` و`DATABASE_URL`
  و`pg` مثبتة — بيطبع رسالة واضحة بدل ما يتظاهر بالنجاح.
- **المطلوب لاحقًا:** نفس متطلبات البند (1) أعلاه.

### 3. أي منطق مالي حقيقي يستخدم `references_log`
- لم يُبنَ أي شيء هنا عمدًا — الجدول والـ model جاهزين فقط كـ "قاعدة"
  قابلة للاستخدام، والمنطق الفعلي (خصم/إضافة أرصدة، ربط بعمليات محددة)
  متروك بالكامل لمرحلة مالية قادمة يقررها صاحب المشروع.
